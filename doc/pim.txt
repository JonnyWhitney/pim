1. INTRODUCTION                                        *pim-introduction*

pim runs the pi coding agent in Neovim. pi runs as a child process in RPC
mode. pim uses `pi --mode rpc` and JSONL over standard input and output.

pim shows the conversation in a read-only Markdown transcript. Write
prompts in the Neovim input buffer below the transcript. pim stores complete
tool-call arguments in the transcript as readable JSON. Fold headers show the
file path for built-in file tools and a command summary for Bash. Edit results
show a diff, write results show syntax-highlighted file content, and Bash
results keep the complete command separate from its output. pim can show the
proposed operation while a permission dialog is open. This preview is
display-only and does not add a message to the model context.
Tool calls are folded by default, including during execution. Results, including
edit diffs, and ! output are left open. Thinking is folded by default.
Each default can be changed through transcript.folds; thinking can also be
hidden. Folds can be toggled with <Tab> or native Neovim fold commands.
Manual choices are preserved per window during updates. Defaults are reapplied
when history is reloaded or a buffer or window is recreated.

Neovim nightly and Pi 0.85.1 or newer are required. The backend is tested
against Pi 0.85.1. Subagents are enabled by default.
The Neovim client is written in Lua without plugin dependencies.
A bundled TypeScript backend is executed by Pi. No user build step is required.
Other Neovim releases are not supported.

The transcript winbar shows the provider, model, thinking level, pi
configuration directory, and context usage. Context usage has the form
`ctx:12k/100k (12%)` and refreshes after each completed assistant response.
pim uses $PI_CODING_AGENT_DIR when it is set. It uses ~/.pi/agent when that
variable is unset.

Start with |:PiStart|. To start Neovim in the pi UI, define this alias:
>sh
    alias pim='nvim -c PiStart'
<

2. COMMANDS                                                *pim-commands*

:PiStart                                                            *:PiStart*
    Open the pi UI. Start pi if it is not running. The cursor moves to the
    input buffer in Normal mode.

    pim reuses an empty initial tab. If one pi window is closed, this
    command restores it. It does not create a second pi layout.

:PiToggle                                                          *:PiToggle*
    Show or hide the pi windows. pi continues to run while the windows hide.
    The pim buffers and input draft remain.

:PiSend [{text}]                                                     *:PiSend*
    Send {text} as a prompt. Without {text}, send the input buffer contents.

:PiAbort                                                            *:PiAbort*
    Clear queued prompts, restore them to input history, and stop the current
    agent run. Stop a shell command directly when one is active.

:PiResume                                                          *:PiResume*
    Select a session for the current working directory. pim loads the
    selected session history into the transcript.

:PiTree                                                                *:PiTree*
    Browse the active session tree. pim disables prompts while the tree is
    open.

    Use j and k to move. p previews the selected entry. q returns from a
    preview to the tree. r forks a selected user prompt. c clones the active
    branch. In the tree, <CR> or q restores the active transcript.
    Branch-summary and compaction entries are hidden. Visible descendants are
    shown under the nearest visible ancestor. Summary content is omitted from
    previews and transcripts. Saved sessions and internal links are preserved.

    pim blocks new, switch, fork, and clone session actions while pi is
    streaming, compacting, running Bash, or retrying. An agent run remains
    busy through queued continuations until pi reports that it settled.

:PiTrust                                                            *:PiTrust*
    Manage project trust for Neovim's current working directory. This command
    works when pi is running or stopped.

    pim resolves symlinks and shows the saved decision. The closest decision
    from an ancestor directory applies when the current directory has no
    direct decision. The picker shows this decision as inherited.

    The picker has three choices:

    Trust
        Save trust for the current directory.

    Trust parent folder
        Save trust for the immediate parent directory. Remove a direct
        decision for the current directory.

    Do not trust
        Save a rejection for the current directory.

    pim reads and writes $PI_CODING_AGENT_DIR/trust.json. It uses
    ~/.pi/agent/trust.json when the environment variable is not set. pim does
    not overwrite malformed or invalid trust data.

    A running pi process does not reload a saved trust decision. Run
    |:PiRestart| after you change trust while pi is running.

:PiNewSession                                                  *:PiNewSession*
    Start a new session. The transcript clears. pi continues to run.

:PiFork                                                                *:PiFork*
    Select an earlier prompt. pi starts a new session at that prompt. pim
    places the prompt in the input buffer so you can edit and send it.

:PiClone                                                              *:PiClone*
    Copy the active pi branch into a new session. The input buffer clears.

:PiModel                                                            *:PiModel*
    Select an available pi model. pim marks the current model.

:PiThinking                                                      *:PiThinking*
    Select a thinking level that the current model supports. pim gets this
    list from pi. Older pi versions use a compatible fallback list.

:PiAgents[!]                                                        *:PiAgents*
    Select and open a subagent invocation from the current parent session.
    Use [!] to include retained invocations from other parent sessions.

:PiAgentTranscript                                        *:PiAgentTranscript*
    Select and open a subagent transcript from the current parent session.

:PiRestart                                                        *:PiRestart*
    Restart pi. pim resumes the current session if its session file exists.

:PiStop[!]                                                           *:PiStop*
    Stop pi and delete the pim windows and buffers, including the input
    draft. pim asks for confirmation. Use [!] to skip confirmation. See
    |pim-leaving|.

:PiLog                                                                *:PiLog*
    Open the event log in a split. Set `debug = true` to include raw JSONL
    traffic.

                                                            *pim-leaving*
Leaving ~

Closing the input window has the same effect as |:PiStop|. pim asks for
confirmation first. `:PiStop!` skips confirmation.

After confirmation, pim closes the pi windows with :quit. Neovim closes
the tab when it has no windows. Neovim exits when it has no tabs. Unsaved
changes can stop the exit, as with |:quit|.

The session file remains after the UI closes. Use |:PiStart| to resume the
session. Use |:PiToggle| to hide the UI without stopping pi.

3. KEYMAPS                                                  *pim-keymaps*

All keymaps apply only to pi buffers. Set different keymaps in
|pim-setup|. The default keymaps follow.

  Normal <CR><CR>      input       Send the prompt.
  <localleader><CR>    input       Send a follow-up after the current run.
  <C-c>                pi buffers  Stop the shell command or agent run.
  <Tab>                transcript  Toggle the fold at the cursor.
  <Up> / <Down>        input       Move through prompt history at the first
                                   or last line.

Insert-mode <CR> inserts a new line. pim does not remap Esc.

pim clears the input after you send it. If pi rejects the prompt, pim
restores it when the input remains empty. If you enter new text, press <Up> to
recall the rejected prompt.

When you abort an agent run, pim first clears queued steering and follow-up
prompts. It puts the first queued prompt in an empty input buffer and keeps
each queued prompt as a separate history entry. If the input has a newer
draft, pim preserves it and adds the queued prompts to history.

                                                              *pim-shell*
Shell commands ~

A prompt that starts with `!` runs as a shell command in pi. A prompt that
starts with `!!` does not add output to the next agent context.
>
  !ls -la     Run the command. Add output to the next prompt context.
  !!ls -la    Run the command. Do not add output to the prompt context.
<
The command uses pi's working directory and environment. pim shows the
output in a fold. A nonzero exit shows `[exit N]`. The `!!` form shows
`[not in context]`. `<C-c>` stops a running command.

Set `bash_passthrough = false` to send these prompts to the agent unchanged.

4. CONFIGURATION                                      *pim-configuration*
                                                              *pim-setup*

Calling setup() is optional. All options have default values.
>lua
  require("pim").setup({
    pi_cmd = "pi",              -- String or list. pim adds --mode rpc.
    args = {},                  -- Additional pi command-line arguments.
    keymaps = {
      submit = "<CR><CR>",
      submit_followup = "<localleader><CR>",
      abort = "<C-c>",
      toggle_fold = "<Tab>",
    },
    input = { min_height = 3, max_height = 15 },
    completion = {
      respect_gitignore = true,
      exclude = { "**/node_modules/**" },
    },
    streaming_submit = "steer", -- Or "followUp".
    bash_passthrough = true,    -- Run prompts that start with ! or !! as shell commands.
    transcript = {
      dividers = true,
      header_highlights = { -- Or false for ordinary Markdown colors only.
        user = "PimUserHeader",
        assistant = "PimAssistantHeader",
        custom = "PimCustomHeader",
      },
      folds = {
        tool_calls = "folded",
        tool_results = "open",
        thinking = "folded", -- "folded", "open", or "hidden".
        bash_output = "open",
      },
    },
    set_title = false,          -- Allow extensions to set 'titlestring'.
    debug = false,              -- Record raw RPC traffic for :PiLog.
  })
<
Invalid option values cause an error. Unknown option keys cause a warning that
includes the full key path.
>
  [pim] ignoring unknown config keys:
    keymaps.submitt
<
The warning does not stop setup(). Valid options still apply.

Message boundaries ~                                    *pim-message-boundaries*

Chat headers are colored by role. Divider lines are displayed on the blank
separator before chat headers, not around internal tool blocks. No divider text
is added to copied Markdown. The Markdown filetype, headings, and code fences
are retained in transcripts and tree previews.

Dividers can be disabled with transcript.dividers = false. Extra header colors
can be disabled with transcript.header_highlights = false. Ordinary Markdown
highlighting is retained in both cases.

Default highlight links are supplied without overwriting user definitions:

  Group                 Default link
  PimUserHeader         Identifier
  PimAssistantHeader    Statement
  PimCustomHeader       Special
  PimDivider            Comment

Each header_highlights value can be set to a Neovim highlight-group name.
Partial overrides are merged with the defaults. Alternatively, pim groups can
be customized directly. A color override can be reapplied with |ColorScheme|:
>lua
  local function set_pim_colors()
    vim.api.nvim_set_hl(0, "PimUserHeader", { fg = "#7dcfff", bold = true })
  end
  vim.api.nvim_create_autocmd("ColorScheme", { callback = set_pim_colors })
  set_pim_colors()
<

5. COMPLETION                                            *pim-completion*

The input buffer has an 'omnifunc'. It can start automatically in two cases.

- Type `/` as the first prompt character to complete pi slash commands. This
  includes extensions, prompt templates, and skills.
- Type `@` at the start of a word to complete a file path. pim uses
  `git ls-files` in a Git repository. Elsewhere, or after a failed Git query,
  files are discovered recursively without another executable. Paths are relative
  to the working directory. Directory symlinks are not followed. Unreadable or
  disappearing entries are skipped. Git ignore rules are not applied by this
  fallback.

By default, Neovim's built-in omni menu is opened automatically in these
contexts. Suggestions are matched by prefix, not fuzzily. These mappings and
completion settings are applied only to the pim input buffer.

pi expands @file references on the server. CTRL-X CTRL-O starts either
completion manually.

OPTIONAL BLINK INTEGRATION                               *pim-blink*

A Blink source is bundled with pim. No separate source plugin is needed.
Integration must be enabled explicitly through Blink's configuration. Installing
Blink alone does not change native completion.

This config callback can be added to an existing lazy.nvim Blink specification.
Existing opts, including menus, keymaps, documentation, ghost text, and selection
settings, are retained. A sources.default list or function must be supplied.
>lua
  config = function(_, opts)
    opts.sources = require("pim.completion.blink").setup(opts.sources)
    require("blink.cmp").setup(opts)
  end,
<
pim must be available on runtimepath when this callback is run. With lazy.nvim,
"JonnyWhitney/pim" can be added to Blink's existing dependencies. Other
dependencies must be kept, including blink.lib for development Blink.

For an existing setup with omni and lazydev, these source options can be retained:
>lua
  sources = {
    default = { "lsp", "omni", "path", "buffer", "lazydev" },
    providers = {
      lazydev = { name = "LazyDev", module = "lazydev.integrations.blink" },
      omni = {
        enabled = function()
          local omnifunc = vim.bo.omnifunc
          return omnifunc ~= "" and omnifunc ~= "v:lua.vim.lsp.omnifunc"
        end,
      },
    },
    per_filetype = {
      minifiles = { inherit_defaults = false },
    },
  },
<
lazydev is not required by pim. Other source lists can be supplied instead.
The helper must be called once, after source options are assembled and before
blink.cmp.setup. A new configuration is returned. Provider pim is registered
with module pim.completion.blink and no fallbacks; the pim ID is reserved.
Existing filetype overrides and inherit_defaults are composed into a dynamic
default-source selector. Filetype overrides must not be added afterwards.

Only pim suggestions are selected in valid input-buffer contexts, even when no
candidates match. omni and other configured sources are retained elsewhere.
Ordinary Markdown and transcript buffers are unaffected. Paths are matched
fuzzily by Blink: @comp can match lua/pim/completion.lua. Command descriptions
and source labels are retained. Explicit replacement ranges prevent duplicate
sigils and respect completion.keyword.range, including full-range mid-token edits.

No selection, insertion, or menu settings are overridden. In particular,
preselect = false and auto_insert = false can be retained. Native omni mappings
and option overrides are removed from an already attached buffer or skipped when
Blink is configured first. Activation survives hide/show and stop/start. If Blink
is disabled after activation, the integration callback must be omitted on the
next Neovim start to restore the default backend. No automatic switch is made.

Blink v1.10.0 is supported. Development v1.10.0-234-gf724653 has also been tested
with blink.lib. Only documented source and configuration interfaces are used.
Other Blink releases have not yet been verified. The optional tests require an
installed Blink checkout; nothing is downloaded by the tests:
>
  mise run test:blink /path/to/blink.cmp '' lua
  mise run test:blink /path/to/blink.cmp /path/to/blink.lib rust
<
Both load orders can be checked by appending blink-first. Real fuzzy matching,
UTF-8, punctuation, automatic triggers, full-range edits, deletion, empty matches,
selection, documentation, and normal/filetype sources are checked in a clean
child Neovim instance. The default test suite requires no Blink dependency and
includes a clean child Neovim check of automatic native popups.

FILE FILTERING

Git ignore filtering is enabled by completion.respect_gitignore by default.
Standard rules from .gitignore, .git/info/exclude, and global exclusions are
applied. Tracked files remain eligible even when matched by these rules.
With respect_gitignore = false, ignored files and directory contents are
included. No implicit exclusions are added for build outputs.

Explicit completion.exclude globs are always applied, including to tracked
files and recursive discovery outside Git or after a failed Git query. Root and
nested node_modules directories and their contents are excluded by default.
A supplied list replaces the defaults. An empty list disables glob exclusions.

A glob is a path pattern with wildcards. Complete paths relative to the current
working directory, not necessarily the Git root, are matched case-sensitively
with / separators. * is matched within one path component; **/ is matched
across zero or more directory levels. Examples:

  *.log                  Root-level logs only.
  **/*.log               Logs at any depth.
  **/build/**            Build directories at any depth.
  **/node_modules/**     Root and nested dependency directories and contents.
  config/private.json    One exact relative path.

Neovim's built-in glob syntax is used. Shell expansion, Git-style negation, and
ordered re-inclusion are not supported. File paths, rather than directory
placeholders, are offered. Quoted references and paths containing whitespace
are not supported by the reference syntax.
>lua
  -- Only Git ignore filtering is disabled; node_modules remains excluded.
  require("pim").setup({ completion = { respect_gitignore = false } })

  -- The default pattern is repeated so it is retained with custom exclusions.
  require("pim").setup({ completion = {
    exclude = { "**/node_modules/**", "**/build/**", "*.log" },
  } })

  -- Both filters are disabled.
  require("pim").setup({ completion = {
    respect_gitignore = false, exclude = {},
  } })
<
Complete candidate lists are cached for ten seconds by directory and completion
settings. Setting changes are applied on the next request. Caches are cleared
when completion is reset. Omni enumeration remains synchronous, with a
two-second Git timeout. Large trees can therefore delay the native popup.
No candidate limit is imposed. Explicit exclusions are applied as filters, not
traversal pruning, so excluded directories may still be scanned.
These settings affect picker candidates only. Manually entered @file references
are not blocked. File access is not protected by these exclusions.

The shared data API provides scheduled discovery for asynchronous consumers:
  require("pim.completion.data").request_files(cwd, callback, is_current)
A cancel function is returned. Git is run asynchronously. Recursive fallback is
scheduled in batches of at most 128 entries. is_current must be supplied by the
consumer to reject changed buffers or contexts. Directory/settings changes and
resets are checked internally. Only complete, current results are cached and
returned. This API is used by the bundled Blink source.

Validation: mise run test completion
A 2,049-file temporary tree is checked for complete enumeration and event-loop
progress. Cancellation, failed Git, symlinks, and simulated filesystem failures
are covered. Individual filesystem calls, Git decoding, sorting, and copying
are not time-bounded. Slow filesystems or very large result sets may cause delays.
The entire candidate list is held in memory.

6. EXTENSION DIALOGS                                        *pim-dialogs*

Extensions send UI requests through pi. pim displays these requests.

- select and confirm requests use |vim.ui.select()|.
- input requests use |vim.ui.input()|.
- editor requests open a scratch split. <CR><CR> submits and q cancels.

Plugins that change vim.ui.* can change these dialogs. The winbar shows
extension status entries and the first line of extension widgets.

pi resolves a timed-out dialog with its default response. pim then
abandons the dialog. pim sends cancellation for an unknown request method.
This prevents a newer extension from waiting without a response.

7. TROUBLESHOOTING                                  *pim-troubleshooting*

Use these commands to check pim:
>
  :checkhealth pim    Check Neovim, pi, and the session directory.
  :PiLog                  Show pim events and pi messages.
<
Set `debug = true` in |pim-setup| to record all raw JSONL lines. The event
log remains available after |:PiStop|. pim clears it immediately before it
starts a new pi process. |:PiNewSession| and |:PiToggle| do not clear it.

pi does not start ~

Check `pi_cmd`. The transcript shows the error and remains open. Correct the
setting and run |:PiRestart|. Use |:checkhealth| to check the pi command.

pi stops ~

The winbar shows the exit code. The notification includes recent pi standard
error output. Run |:PiRestart| to resume the session.

The transcript does not update ~

Check |:PiLog| for handler errors. pim handles each incoming message
separately. A bad message does not stop later messages. Reopen the UI if the
transcript buffer was deleted.

pi does not respond ~

pim fails an unanswered command after 30 seconds. It shows `pi did not
respond`. Shell commands do not have this timeout because their response waits
for the command to end.

A message is missing ~

pim drops an unterminated line after 8 MiB. It then reads the next line.
Check |:PiLog| and verify that `pi_cmd` starts pi.

An option has no effect ~

Check |:messages| for an unknown-option warning. See |pim-configuration|.

Known limitations ~

The built-in |vim.ui.select()| cannot close automatically after a timeout. pi
has already selected its default response. This affects appearance only. UI
plugins can provide automatic closing.

Queued steer and follow-up messages use virtual lines. You cannot yank them.

SUBAGENTS                                                     *pim-subagents*

Dynamic children are created by the calling model through the subagent tool.
No role definitions or agent files are loaded. The backend is enabled only in
PIM RPC mode. Native Pi terminal rendering is not provided.

Activation can be disabled through |pim-setup|: >lua
  require("pim").setup({ subagents = { enabled = false } })
<
When disabled, no backend argument or private host environment is added.
Unknown nested configuration keys are reported with their full paths.
The bundle and transcript root are checked by :checkhealth pim. Startup is
rejected if the enabled bundle is missing. Imports are supplied by Pi.

Tool input uses one agents array with one to eight entries: >json
  {"agents":[{"label":"review","prompt":"Review the parser.",
    "tools":["read","grep","find","ls"],
    "model":"anthropic/claude-sonnet-4-6","thinkingLevel":"high"}]}
<
Required fields: label, prompt, tools, model, thinkingLevel.
An empty tools array is permitted. An exact provider/model identifier is
required. Thinking levels are off, minimal, low, medium, high, xhigh, max.
Levels may be clamped by Pi for the selected model.
No model, tools, thinking level, or parent conversation is inherited.

Optional fields:
  systemPrompt       Caller-supplied system instructions.
  systemPromptMode   append (default) or replace. A nonempty replacement is
                     required. Enabled project context may still be added.
  context            Additional caller text, separated from the task.
  projectContext     true (default) or false.
  cwd                Child directory; the parent directory is used by default.

Task text is supplied through standard input. System prompts are supplied
through temporary files with user-only permissions and removed afterward.
Project resources are approved only when the parent project is trusted and
its canonical cwd is unchanged. Trust is not transferred to a different cwd.
With projectContext=false, context files, extension discovery, skills, and
prompt-template discovery are disabled. Model settings and credentials remain
available. A private child policy guard is explicitly loaded in every child.
These controls are not an operating-system sandbox.

At most four child processes are run across all calls. Parallel tool lists are
restricted to built-in read, grep, find, ls. Extension discovery is disabled
in parallel mode to prevent overrides. All parallel lists are checked before
execution. A single child can use any available Pi tool except subagent.
Unknown tools and unresolved models are reported as child failures. Other
children are not stopped by one child's failure.

Parent abort terminates all children with SIGTERM. SIGKILL is sent after
5000 ms if needed. Final results and nested usage are returned in input order.
Parent output is capped at 50 KiB and 2000 lines in aggregate. A smaller
per-child share is used for parallel output. Truncation is marked. Details
contain bounded summaries and file references, not the full child history.

Storage:
  stdpath("data")/pim/subagents/<parent-session-id>/<invocation-id>/
    invocation.json
    <child-id>.jsonl
    <child-id>.summary.json

Full events, configuration, thinking, tool calls, usage, and final output are
stored. Directories use 0700; files use 0600. Symlink storage paths are
rejected. Manifests are replaced atomically. Complete JSONL records remain
readable after interruption. Sensitive prompts and outputs may be included. No automatic cleanup is
performed.

The parent transcript renders only the child count and aggregate statuses.
Use |:PiAgents| or |:PiAgentTranscript| to open a read-only inspector. One
pim://subagents/<invocation-id> buffer is reused for each invocation. Parallel
children have separate foldable sections. Live parent updates cause only new
complete JSONL records to be read. Completed transcripts can be reopened after
a restart. Incomplete final lines are retained until they are completed.
Malformed records are reported and skipped. Later valid records still render.
Missing or unsafe transcript paths are shown as unavailable.

Targeted stop and cleanup commands are not yet available.

DEVELOPMENT                                                   *pim-development*

Node.js 24.21.0 (the latest LTS release) and pnpm 12.4.2 are pinned in
pi-extensions/mise.toml. These tool versions are scoped to pi-extensions/.
Node.js 24.21.0 or a newer 24.x release is required for backend development.
Other Node.js majors are rejected by the backend development commands.
Pi API development dependencies are pinned to 0.85.1.

Strict type checking is provided by tsgo from @typescript/native-preview.
TypeScript 7.0.2 is included for editors. Linting is provided by Oxlint 1.83.0;
formatting is provided by Oxfmt 0.68.0. The extension and its tests are covered.
No development toolchain is required by the Neovim client.

The TypeScript package, lockfile, configs, dependencies, scripts, and tests
are contained in pi-extensions/. Oxfmt is restricted to that package. No
Oxfmt config is applied to the repository root or Lua client. Shared JSON
fixtures remain in tests/fixtures/subagents/ and are not formatted by Oxfmt.
Backend checks are delegated by the root mise tasks.

  mise install                    Install Lua development tools.
  mise -C pi-extensions install    Install backend development tools.
  mise -C pi-extensions exec -- pnpm install --frozen-lockfile
                                  Install locked backend dependencies.
  mise run fmt                    Format Lua and the Pi extension.
  mise run fmt:check              Check both formats without changes.
  mise run lint                   Run lua-language-server and Oxlint.
  mise run typecheck              Run strict tsgo checking.
  mise run verify                 Run all checks, tests, and health checks.
  mise -C pi-extensions run verify Run backend checks only.
  mise -C pi-extensions run fmt    Format the backend package only.

Formatting differences, lint warnings, and type errors are rejected by verify.
